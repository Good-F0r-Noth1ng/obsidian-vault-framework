# Publishing Boundary

Publish the framework, not a personal vault.

## Safe to include

- Directory scaffolding and empty placeholders.
- Original templates, governance rules, and scripts.
- Skills that do not contain secrets, private paths, or third-party restricted text.
- Fully fictional or deliberately redacted examples.

## Do not include without a separate rights review

- Papers, books, slides, scans, subscriptions, or other copyrighted source files.
- OCR output, extracted figures, and derived artifacts from restricted sources.
- Personal notes, research data, credentials, local paths, account names, or private collaboration details.

## Before changing visibility to public

1. Review tracked files with `git status` and `git ls-files`.
2. Search for credentials, personal identifiers, and absolute paths.
3. Confirm the license covers every original file being published.
4. Check that `.gitignore` still excludes live vault content.
